databricks-genre-model, explained step by step

From the Chinook view to a scheduled Databricks job and a token-protected serving endpoint

This document walks through everything that was built for the second part of the Bases de Datos assignment: the same music-genre model as pipeline-db-ml, now trained every day by a Databricks job and published on a Databricks Model Serving endpoint that anyone with the URL and an access token can query.

Each step explains what was done, why it was done that way and how to check that it works, with the real code, the real commands and the real output of the first run.

1. The big picture

The question is the same as in the first assignment: a customer walks into the music store, we know three things about them (what kind of email they use, their country and their city) and we want to guess which music genre they are most likely to buy. What the assignment asks for now is different infrastructure:

  1. A Databricks job that trains the model periodically.
  2. The trained model published on a Databricks serving endpoint.
  3. For the professor: the endpoint URL, an access token and an example of how to query it.

Everything lives in one Git repository. One command (databricks bundle deploy) copies the code and the data into the Databricks workspace and creates the job; the job then does the rest by itself, every day.

Compare with the first assignment. There, a cron container wrote a .pkl file into a shared folder and a FastAPI container read it. Here the "file" is a versioned model in a registry, the "cron" is a scheduled job, and the "API container" is a managed endpoint. Nobody administers a virtual machine.

2. Vocabulary you need

Databricks Free Edition. A free Databricks account with one workspace. It runs only serverless compute, allows at most 5 concurrent job tasks per account, a limited number of serving endpoints (CPU only), outbound internet only to a list of trusted domains, and a daily fair-use quota: if you exceed it, compute is switched off for the rest of the day. (free-edition-limitations)
Serverless compute. You do not create or size a cluster. You submit work and Databricks provides the machines, then releases them. For a Python task you only declare which libraries it needs (an environment).
Asset bundle. A folder with a databricks.yml file that describes code, files and resources (jobs, schemas...) as YAML. databricks bundle deploy uploads the folder to the workspace and creates or updates the resources; databricks bundle run starts a job. The docs now also call them "Declarative Automation Bundles"; the commands are the same.
Job and task. A job is a named, schedulable unit of work. It contains tasks (here, four Python scripts) with dependencies between them: a task starts only when the ones it depends_on have succeeded. Each execution is a run, with its own id, log and result.
Delta table and Unity Catalog. A Delta table is Databricks' table format (Parquet files plus a transaction log). Unity Catalog is the governance layer that names everything with three levels, catalog.schema.object: our tables are workspace.chinook.customer and so on, the view is workspace.chinook.vw_cliente_genero and the model is workspace.chinook.genero_cliente.
MLflow run and registered model. An MLflow run is one training session with its parameters, metrics (our accuracy) and files (our classification report). A registered model is a named entry in the registry; every time we log a new model under that name it gets a new version (1, 2, 3...).
Alias. A movable label that points to one version of a registered model, like a Git tag you can move. We use Champion: "the version that should be served". Code loads models:/workspace.chinook.genero_cliente@Champion without knowing the number.
pyfunc model. MLflow's generic Python model: a class with a predict(context, model_input) method. Wrapping the scikit-learn pipeline in a pyfunc lets us decide the output format (genre plus top 3) and clean the input before predicting.
Serving endpoint. A managed HTTPS service that loads a registered model version and answers POST /serving-endpoints/<name>/invocations with predictions. It has a size (Small) and can be updated to a new version without downtime.
Scale to zero. An endpoint option: when there is no traffic the endpoint releases its compute and costs nothing; the next request wakes it up, so the first call after an idle period takes longer.
Personal access token (PAT). A long random string that acts as a password for the Databricks REST API on behalf of the user who created it. It is sent in the header Authorization: Bearer <token>. It has a lifetime, can be revoked, and must never be committed. (dev-tools/auth/pat)
Quartz cron. The schedule syntax Databricks jobs use. Unlike Linux cron it has a seconds field first: 0 0 3 * * ? reads "second 0, minute 0, hour 3, every day of the month, every month, any day of the week", that is, every day at 03:00. The ? means "no specific value" and is required in one of the two day fields.

Two things could not be kept:

  • The database connection. On Free Edition, outbound internet is "restricted to a limited set of trusted domains", so a job cannot open a connection to the Postgres on EC2 or to Supabase. The data has to live inside Databricks (Step 1).
  • The nested top_3 list. A model in Unity Catalog needs a signature (a declared input and output schema). Flat columns (top_1, p_1, ...) give a simple, clean signature; the information is the same.

4. Step 1. The data: from the Postgres dump to CSVs to Delta tables

4.1 Why CSVs, and why only five tables

What. scripts/chinook_to_csv.py reads the same dump the first assignment loaded into Postgres and writes the five tables the view needs: genre, track, invoice_line, invoice and customer. The CSVs are committed (they are small) and travel to the workspace with the bundle.
Why. The job cannot reach any outside database (Free Edition limitation). Parsing the dump needs no server and no download, and it guarantees the data is byte-for-byte the data of the first assignment.

The dump writes one row per line, with SQL Server style N'...' strings and bare NULLs:

pipeline-db-ml/db/init/01_chinook.sql (lines 222 to 224 and 4405)
INSERT INTO genre (genre_id, name) VALUES
    (1, N'Rock'),
    (2, N'Jazz'),
...
    (2, N'Leonie', N'Köhler', NULL, N'Theodor-Heuss-Straße 34', N'Stuttgart', NULL, N'Germany', N'70174', N'+49 0711 2842222', NULL, N'leonekohler@surfeu.de', 5),

The script drops the N prefix and marks NULL only outside quoted strings, then lets Python's csv module (with ' as the quote character) split the values. The full parser is in the repository; its self-test checks the counts and a few tricky values:

4.2 Task 1: CSV to Delta tables, then the view

src/load_chinook.py (main)
def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--data-dir", required=True)
    args = ap.parse_args()

    spark = SparkSession.builder.getOrCreate()
    spark.sql(f"CREATE SCHEMA IF NOT EXISTS {CATALOG}.{SCHEMA}")

    for table in TABLES:
        path = f"{args.data_dir.rstrip('/')}/{table}.csv"
        raw, how = read_csv(spark, path)
        df = typed(table, raw)
        (df.write.format("delta").mode("overwrite").option("overwriteSchema", "true")
           .saveAsTable(f"{CATALOG}.{SCHEMA}.{table}"))
        n = spark.table(f"{CATALOG}.{SCHEMA}.{table}").count()
        print(f"{CATALOG}.{SCHEMA}.{table}: {n} rows ({how})")

    spark.sql(view_sql(args.data_dir))
    rows = spark.table(VIEW).count()
    print(f"{VIEW}: {rows} rows (expected 2240)")
    if rows == 0:
        raise SystemExit("the view is empty")
  • Types. CSV has no types. A CASTS table (full file in the appendix) gives each id its int, prices their decimal(10,2), and the invoice date (2021/1/1 in the dump) a timestamp, as in the Postgres CREATE TABLEs.
  • Overwrite. Every run rewrites the tables (mode("overwrite")), so a run is always reproducible from the files in the bundle.
  • The schema is created by the task (CREATE SCHEMA IF NOT EXISTS workspace.chinook), not declared in the bundle; Step 2 explains why.

4.3 The view, unchanged

sql/vw_cliente_genero.sql
-- Vista para el modelo predictivo: 4 campos
--   tipo_correo : proveedor del correo (texto entre '@' y el primer '.'): gmail, yahoo, hotmail, embraer...
--   pais        : país del cliente
--   ciudad      : ciudad del cliente
--   genero      : género musical de cada track comprado por el cliente
-- Una fila por track comprado: customer -> invoice -> invoice_line -> track -> genre
-- Misma vista que pipeline-db-ml/db/view.sql, con nombres de tres niveles de Unity Catalog.

CREATE OR REPLACE VIEW workspace.chinook.vw_cliente_genero AS
SELECT
    lower(split_part(split_part(c.email, '@', 2), '.', 1)) AS tipo_correo,
    c.country AS pais,
    c.city    AS ciudad,
    g.name    AS genero
FROM workspace.chinook.customer     c
JOIN workspace.chinook.invoice      i  ON i.customer_id = c.customer_id
JOIN workspace.chinook.invoice_line il ON il.invoice_id = i.invoice_id
JOIN workspace.chinook.track        t  ON t.track_id    = il.track_id
JOIN workspace.chinook.genre        g  ON g.genre_id    = t.genre_id;

Databricks SQL has split_part with the same meaning as in Postgres, so the SQL is the same as in the first assignment; only the table names gained the workspace.chinook. prefix (and the \c chinook psql command disappeared). The task reads this file from the bundle and runs it.

The development-mode trap.
Bundle templates put mode: development on the dev target. That mode is meant for personal experiments: it pauses every schedule and prefixes resource names with [dev <user>] (and schemas with dev_<user>_). The assignment needs the daily training active under a plain name, so the target has no mode at all (second commit of the repository: "drop development mode so the daily schedule stays active"), and the schema is created by the load task instead of being a bundle resource.

6.2 The wrapper: same contract as the old API

src/genre_model.py
def extraer_tipo_correo(valor) -> str:
    """Same rule as the view vw_cliente_genero (and PredictorRequest in pipeline-db-ml):
    text between '@' and the first '.', lower case. Accepts "gmail" or "ana@yahoo.com.br"."""
    valor = str(valor).strip().lower()
    if "@" in valor:
        valor = valor.split("@", 1)[1]
    return valor.split(".")[0]


def preparar_entrada(model_input) -> pd.DataFrame:
    if not isinstance(model_input, pd.DataFrame):
        model_input = pd.DataFrame(model_input)
    faltan = [c for c in FEATURES if c not in model_input.columns]
    if faltan:
        raise ValueError(f"faltan columnas: {faltan}; se esperan {FEATURES}")
    X = model_input[FEATURES].copy()  # by name: dataframe_records does not guarantee column order
    X["tipo_correo"] = X["tipo_correo"].map(extraer_tipo_correo)
    X["pais"] = X["pais"].astype(str).str.strip()
    X["ciudad"] = X["ciudad"].astype(str).str.strip()
    return X


class GenreModel(_Base):
    def __init__(self, pipeline):
        self.pipeline = pipeline

    def predict(self, context, model_input, params=None):
        X = preparar_entrada(model_input)
        generos = self.pipeline.predict(X)
        probas = self.pipeline.predict_proba(X)
        clases = [str(c) for c in self.pipeline.classes_]
        filas = []
        for genero, fila in zip(generos, probas):
            orden = sorted(range(len(clases)), key=lambda k: fila[k], reverse=True)[:3]
            salida = {"genero": str(genero)}
            for pos in range(3):
                if pos < len(orden):
                    salida[f"top_{pos + 1}"] = clases[orden[pos]]
                    salida[f"p_{pos + 1}"] = round(float(fila[orden[pos]]), 4)
                else:
                    salida[f"top_{pos + 1}"] = ""
                    salida[f"p_{pos + 1}"] = 0.0
            filas.append(salida)
        return pd.DataFrame(filas, columns=OUTPUT_COLUMNS)
  • extraer_tipo_correo is the same rule as the view: the endpoint accepts "yahoo" or a full address like "ana@yahoo.com.br", and the model always sees yahoo.
  • Columns are selected by name. The docs warn that dataframe_records does not guarantee column order (score-custom-model-endpoints); selecting by name makes the order irrelevant.
  • predict_proba gives one probability per genre; sorting gives the top 3, rounded to 4 decimals.

Create vs update. The first run finds no endpoint and creates it with one served entity: model workspace.chinook.genero_cliente, the alias's version, size Small, scale to zero on. Every later run finds it and calls update_config with the new version. If the endpoint already serves that version (for example when a run is repeated after a failure in task 4), it does nothing.
No downtime. During an update the old configuration keeps serving until the new one is ready (create-manage-serving-endpoints). The _and_wait calls block until that happens, up to 30 minutes.
Why the job owns the endpoint. A bundle can also declare an endpoint as a resource, but its model version would then be fixed in YAML and every deploy would push it back, fighting the job's daily update. Letting the job create or update the endpoint means one run trains and publishes, with no manual step in the UI.

9.1 What every run does

Each run registers a new version N of workspace.chinook.genero_cliente, moves Champion to N, and updates the endpoint to N. The URL and the token never change, so the professor's example keeps working across retrains. This was visible while the second run (started by hand right after the first) was updating: the endpoint reported ready: READY and config_update: IN_PROGRESS, still serving version 1, with version 2 listed as the pending configuration (Container creation pending.), and queries kept returning HTTP 200.

Because the data does not change, version N predicts the same as version N−1. In a real store with new purchases every day, the same job would pick them up without any change to the code.

10.1 How to generate it

  2. Next to Access tokens, click Manage → Generate new token.
  3. Comment (name): profesor-bases-de-datos. Lifetime: 60 days. If the dialog offers a scope, choose "Other APIs" and limit it to serving endpoints.

Source: https://docs.databricks.com/aws/en/dev-tools/auth/pat ("Save the token securely and don't share it").

10.2 What it grants

A personal access token acts as its owner. Unscoped, it can call any Databricks REST API the owner can, in this workspace only: that is why the lifetime is short, why a scope is used when the UI offers one, and why it is shared only with the professor. On this endpoint it is sent as Authorization: Bearer <TOKEN>; requests without a valid token are rejected. Personal access tokens work on standard endpoints like this one; route-optimized endpoints would require OAuth instead.

10.3 How to revoke it

Same page (Settings → Developer → Access tokens → Manage): revoke the token profesor-bases-de-datos. It also expires by itself after 60 days, and Databricks revokes any token unused for 90 days. Revoking it does not affect the job or the endpoint, which use their own identity.

11.2 Costs and the Free Edition quota

  • Free Edition has no bill. The limit is the fair-use quota: exceeding it switches compute off for the rest of the day. One run a day of a few short tasks stays far below it.
  • The expensive part of a run is waiting for the endpoint to be built, not our own compute: training takes seconds.
  • Free Edition allows a limited number of active serving endpoints (the number is not published) and no GPU; this project uses one CPU endpoint of size Small.
  • Per-request limits of Model Serving (payload size, execution time) are listed in model-serving-limits; a request with a few rows is far below them.

11.3 Scale to zero

With no traffic, the endpoint releases its compute. The next request wakes it up and takes noticeably longer than the following ones; a client should use a generous timeout (the local client uses 120 seconds). If the professor's first call is slow, a second call answers at normal speed.

11.4 Tearing it down (described, not run)

# 1. remove what the bundle created: the job and the uploaded files
databricks bundle destroy -t dev

# 2. the endpoint was created by the job, not by the bundle, so delete it explicitly
databricks serving-endpoints delete genero-cliente

# 3. optional, in the SQL editor: tables, view and registered model live in the schema
DROP SCHEMA workspace.chinook CASCADE;

# 4. revoke the professor's token (Settings > Developer > Access tokens)

Order matters: destroying the bundle first stops the schedule, so no run recreates the endpoint after step 2. None of these steps were run; the project stays live for grading.

src/load_chinook.py
"""Task 1: load the five Chinook CSVs into Delta tables and (re)create the view vw_cliente_genero.

Reads <data-dir>/{genre,track,invoice_line,invoice,customer}.csv (bundle workspace files), writes
workspace.chinook.<table> (overwrite) and runs sql/vw_cliente_genero.sql.
"""
import argparse
import os

from pyspark.sql import SparkSession
from pyspark.sql import functions as F

CATALOG = "workspace"
SCHEMA = "chinook"
VIEW = f"{CATALOG}.{SCHEMA}.vw_cliente_genero"

# Column types from the CREATE TABLE statements of the Postgres dump; everything else stays string.
CASTS = {
    "genre": {"genre_id": "int"},
    "track": {"track_id": "int", "album_id": "int", "media_type_id": "int", "genre_id": "int",
              "milliseconds": "int", "bytes": "int", "unit_price": "decimal(10,2)"},
    "invoice_line": {"invoice_line_id": "int", "invoice_id": "int", "track_id": "int",
                     "unit_price": "decimal(10,2)", "quantity": "int"},
    "invoice": {"invoice_id": "int", "customer_id": "int", "total": "decimal(10,2)"},
    "customer": {"customer_id": "int", "support_rep_id": "int"},
}
TABLES = list(CASTS)

VIEW_SQL_FALLBACK = f"""
CREATE OR REPLACE VIEW {VIEW} AS
SELECT
    lower(split_part(split_part(c.email, '@', 2), '.', 1)) AS tipo_correo,
    c.country AS pais,
    c.city    AS ciudad,
    g.name    AS genero
FROM {CATALOG}.{SCHEMA}.customer     c
JOIN {CATALOG}.{SCHEMA}.invoice      i  ON i.customer_id = c.customer_id
JOIN {CATALOG}.{SCHEMA}.invoice_line il ON il.invoice_id = i.invoice_id
JOIN {CATALOG}.{SCHEMA}.track        t  ON t.track_id    = il.track_id
JOIN {CATALOG}.{SCHEMA}.genre        g  ON g.genre_id    = t.genre_id
"""


def read_csv(spark, path):
    """spark.read first; if Spark cannot reach workspace files, read with pandas and convert."""
    try:
        df = (spark.read.option("header", "true").option("inferSchema", "false")
              .option("quote", '"').option("escape", '"').option("encoding", "UTF-8")
              .csv(path))
        df.limit(1).collect()
        return df, "spark.read"
    except Exception as e:  # noqa: BLE001 - fall back on any read failure
        print(f"spark.read failed for {path} ({type(e).__name__}: {str(e)[:200]}); using pandas")
    import pandas as pd
    pdf = pd.read_csv(path, dtype=str, keep_default_na=False, encoding="utf-8")
    pdf = pdf.astype(object).where(pdf != "", None)
    schema = ", ".join(f"`{c}` string" for c in pdf.columns)
    return spark.createDataFrame(pdf.values.tolist(), schema=schema), "pandas"


def typed(table, df):
    for col, typ in CASTS[table].items():
        df = df.withColumn(col, F.col(col).cast(typ))
    if table == "invoice":
        # the dump writes dates as 2021/1/1
        df = df.withColumn("invoice_date", F.to_timestamp(F.col("invoice_date"), "yyyy/M/d"))
    return df


def view_sql(data_dir):
    """Read sql/vw_cliente_genero.sql next to the bundle's src/ and data/; inline copy as fallback."""
    candidates = []
    try:
        candidates.append(os.path.join(os.path.dirname(os.path.dirname(os.path.abspath(__file__))),
                                       "sql", "vw_cliente_genero.sql"))
    except NameError:  # __file__ is not always defined in a job's python task
        pass
    candidates.append(os.path.join(os.path.dirname(data_dir.rstrip("/")), "sql", "vw_cliente_genero.sql"))
    for path in candidates:
        try:
            with open(path, encoding="utf-8") as fh:
                text = fh.read()
            print(f"view SQL read from {path}")
            break
        except OSError as e:
            print(f"cannot read {path}: {e}")
    else:
        print("view SQL: using the inlined copy")
        return VIEW_SQL_FALLBACK.strip()
    lines = [ln for ln in text.splitlines() if not ln.strip().startswith("--")]
    return "\n".join(lines).strip().rstrip(";").strip()


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--data-dir", required=True)
    args = ap.parse_args()

    spark = SparkSession.builder.getOrCreate()
    spark.sql(f"CREATE SCHEMA IF NOT EXISTS {CATALOG}.{SCHEMA}")

    for table in TABLES:
        path = f"{args.data_dir.rstrip('/')}/{table}.csv"
        raw, how = read_csv(spark, path)
        df = typed(table, raw)
        (df.write.format("delta").mode("overwrite").option("overwriteSchema", "true")
           .saveAsTable(f"{CATALOG}.{SCHEMA}.{table}"))
        n = spark.table(f"{CATALOG}.{SCHEMA}.{table}").count()
        print(f"{CATALOG}.{SCHEMA}.{table}: {n} rows ({how})")

    spark.sql(view_sql(args.data_dir))
    rows = spark.table(VIEW).count()
    print(f"{VIEW}: {rows} rows (expected 2240)")
    if rows == 0:
        raise SystemExit("the view is empty")


if __name__ == "__main__":
    main()

src/genre_model.py
"""MLflow pyfunc wrapper around the scikit-learn pipeline (OneHotEncoder -> LogisticRegression).

Input: a DataFrame with columns tipo_correo, pais, ciudad (tipo_correo may be a full email).
Output: a DataFrame with genero, top_1, p_1, top_2, p_2, top_3, p_3 (same contract as the
POST /api/model of pipeline-db-ml: the predicted genre plus the top 3 with probabilities).

Logged with code_paths=[this file], so the serving container can import it as `genre_model`.
"""
import pandas as pd

try:  # mlflow is not needed to fit or test the pipeline locally
    from mlflow.pyfunc import PythonModel as _Base
except ImportError:  # pragma: no cover
    _Base = object

FEATURES = ["tipo_correo", "pais", "ciudad"]
TARGET = "genero"
OUTPUT_COLUMNS = ["genero", "top_1", "p_1", "top_2", "p_2", "top_3", "p_3"]


def extraer_tipo_correo(valor) -> str:
    """Same rule as the view vw_cliente_genero (and PredictorRequest in pipeline-db-ml):
    text between '@' and the first '.', lower case. Accepts "gmail" or "ana@yahoo.com.br"."""
    valor = str(valor).strip().lower()
    if "@" in valor:
        valor = valor.split("@", 1)[1]
    return valor.split(".")[0]


def preparar_entrada(model_input) -> pd.DataFrame:
    if not isinstance(model_input, pd.DataFrame):
        model_input = pd.DataFrame(model_input)
    faltan = [c for c in FEATURES if c not in model_input.columns]
    if faltan:
        raise ValueError(f"faltan columnas: {faltan}; se esperan {FEATURES}")
    X = model_input[FEATURES].copy()  # by name: dataframe_records does not guarantee column order
    X["tipo_correo"] = X["tipo_correo"].map(extraer_tipo_correo)
    X["pais"] = X["pais"].astype(str).str.strip()
    X["ciudad"] = X["ciudad"].astype(str).str.strip()
    return X


class GenreModel(_Base):
    def __init__(self, pipeline):
        self.pipeline = pipeline

    def predict(self, context, model_input, params=None):
        X = preparar_entrada(model_input)
        generos = self.pipeline.predict(X)
        probas = self.pipeline.predict_proba(X)
        clases = [str(c) for c in self.pipeline.classes_]
        filas = []
        for genero, fila in zip(generos, probas):
            orden = sorted(range(len(clases)), key=lambda k: fila[k], reverse=True)[:3]
            salida = {"genero": str(genero)}
            for pos in range(3):
                if pos < len(orden):
                    salida[f"top_{pos + 1}"] = clases[orden[pos]]
                    salida[f"p_{pos + 1}"] = round(float(fila[orden[pos]]), 4)
                else:
                    salida[f"top_{pos + 1}"] = ""
                    salida[f"p_{pos + 1}"] = 0.0
            filas.append(salida)
        return pd.DataFrame(filas, columns=OUTPUT_COLUMNS)
src/deploy_endpoint.py
"""Task 3: publish the Champion version of workspace.chinook.genero_cliente on the endpoint genero-cliente.

Creates the endpoint (Small, scale to zero) if it does not exist, otherwise updates its config to the
new version; waits until it is ready. Auth is the job's ambient identity (WorkspaceClient()).
The old config keeps serving until the new one is ready, so a daily update has no downtime.
"""
import argparse
from datetime import timedelta

ENDPOINT = "genero-cliente"
MODEL_NAME = "workspace.chinook.genero_cliente"
ALIAS = "Champion"
TIMEOUT = timedelta(minutes=30)


def version_from_task_value():
    try:
        from databricks.sdk.runtime import dbutils
        v = dbutils.jobs.taskValues.get(taskKey="train_model", key="model_version", debugValue="")
        return str(v) if v else None
    except Exception as e:  # noqa: BLE001
        print(f"task value not available ({type(e).__name__})")
        return None


def champion_version():
    import mlflow
    from mlflow.tracking import MlflowClient
    mlflow.set_registry_uri("databricks-uc")
    mv = MlflowClient(registry_uri="databricks-uc").get_model_version_by_alias(MODEL_NAME, ALIAS)
    return str(mv.version)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--data-dir", default=None)  # accepted for symmetry with the other tasks
    ap.parse_args()

    from databricks.sdk import WorkspaceClient
    from databricks.sdk.errors import NotFound, ResourceDoesNotExist
    from databricks.sdk.service.serving import EndpointCoreConfigInput, ServedEntityInput

    w = WorkspaceClient()

    alias_version = champion_version()
    task_version = version_from_task_value()
    if task_version and task_version != alias_version:
        print(f"note: task value says version {task_version}, alias {ALIAS} says {alias_version}; using the alias")
    version = alias_version
    print(f"{MODEL_NAME}@{ALIAS} = version {version}")

    entity = ServedEntityInput(
        entity_name=MODEL_NAME,
        entity_version=version,
        workload_size="Small",
        scale_to_zero_enabled=True,
    )

    try:
        existing = w.serving_endpoints.get(ENDPOINT)
    except (NotFound, ResourceDoesNotExist):
        existing = None

    if existing is None:
        print(f"creating endpoint {ENDPOINT} with version {version} (waiting up to {TIMEOUT})")
        endpoint = w.serving_endpoints.create_and_wait(
            name=ENDPOINT,
            config=EndpointCoreConfigInput(name=ENDPOINT, served_entities=[entity]),
            timeout=TIMEOUT,
        )
    else:
        served = [(e.entity_name, str(e.entity_version))
                  for e in ((existing.config.served_entities if existing.config else None) or [])]
        updating = existing.state and existing.state.config_update and \
            existing.state.config_update.value == "IN_PROGRESS"
        if updating:
            print(f"endpoint {ENDPOINT} is updating; waiting for it first")
            existing = w.serving_endpoints.wait_get_serving_endpoint_not_updating(ENDPOINT, timeout=TIMEOUT)
            served = [(e.entity_name, str(e.entity_version))
                      for e in ((existing.config.served_entities if existing.config else None) or [])]
        if served == [(MODEL_NAME, version)]:
            print(f"endpoint {ENDPOINT} already serves version {version}; no update")
            endpoint = existing
        else:
            print(f"updating endpoint {ENDPOINT}: {served} -> {MODEL_NAME} v{version} (waiting up to {TIMEOUT})")
            endpoint = w.serving_endpoints.update_config_and_wait(
                name=ENDPOINT,
                served_entities=[entity],
                timeout=TIMEOUT,
            )

    state = endpoint.state
    ready = state.ready.value if state and state.ready else None
    config_update = state.config_update.value if state and state.config_update else None
    print(f"endpoint {ENDPOINT}: ready={ready} config_update={config_update}")
    for e in (endpoint.config.served_entities if endpoint.config else None) or []:
        print(f"  serves {e.entity_name} version {e.entity_version}")
    host = w.config.host.rstrip("/")
    print(f"invocation URL: {host}/serving-endpoints/{ENDPOINT}/invocations")
    if ready != "READY":
        raise SystemExit(f"endpoint {ENDPOINT} is not READY (ready={ready})")


if __name__ == "__main__":
    main()

"""Task 4: query the endpoint genero-cliente with three known rows; fail the job if it does not answer."""
import argparse
import json
import sys

ENDPOINT = "genero-cliente"
ROWS = [
    {"tipo_correo": "yahoo", "pais": "Germany", "ciudad": "Berlin"},
    {"tipo_correo": "gmail", "pais": "Brazil", "ciudad": "São Paulo"},
    {"tipo_correo": "ana@yahoo.com.br", "pais": "Brazil", "ciudad": "São Paulo"},
]


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--data-dir", default=None)  # accepted for symmetry with the other tasks
    ap.parse_args()

    from databricks.sdk import WorkspaceClient

    w = WorkspaceClient()
    response = w.serving_endpoints.query(name=ENDPOINT, dataframe_records=ROWS)
    predictions = response.predictions or []
    for row, pred in zip(ROWS, predictions):
        print(json.dumps({"entrada": row, "prediccion": pred}, ensure_ascii=False))

    if len(predictions) != len(ROWS):
        print(f"expected {len(ROWS)} predictions, got {len(predictions)}: {predictions!r}")
        sys.exit(1)
    empty = [i for i, p in enumerate(predictions) if not (isinstance(p, dict) and p.get("genero"))]
    if empty:
        print(f"empty genero in predictions {empty}: {predictions!r}")
        sys.exit(1)

    berlin = predictions[0].get("genero")
    print(f"yahoo/Germany/Berlin -> {berlin} ({'Metal, as the previous model' if berlin == 'Metal' else 'not Metal'})")
    print("smoke test passed")


if __name__ == "__main__":
    main()
